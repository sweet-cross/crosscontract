# Document project scoping and the three data-removal operations

## Context
**Part of PRD:** [`2026-08-06-client-project-scoped-writes.md`](../../prds/2026-08-06-client-project-scoped-writes.md)

`docs/client/index.md` currently describes two removal operations and presents
`drop_data()` as the way to delete all data. With `confirm_delete_all` there are now
three, they differ in project scope and required contract status, and the existing
guidance is misleading. This task brings the user-facing documentation in line.

### The removal-operations table

Replace the existing two-row table. The **Scope** column is the new information — it is
what the reader cannot infer from the method names:

| Method | Scope | Required status | Reversible? |
| --- | --- | --- | --- |
| `delete_data(filters=...)` | Rows matching the filters, within your project | `Active` | No, but other rows are preserved |
| `delete_data({}, confirm_delete_all=True)` | Every row **your project** owns under this contract | `Active` | No |
| `drop_data()` | The entire storage table, across **all** projects | `Retired` | No — all data is lost |

### Prose to add

**On `confirm_delete_all`.** Explain that an empty `filters` mapping alone raises, and
why: `{}` is the value a bug produces — a comprehension over user input where every value
filtered out — so intent and malfunction would otherwise be indistinguishable at the call
site. The flag cannot arise accidentally. Example:

```python
resource.delete_data(filters={}, confirm_delete_all=True)
```

**On `project_name`.** Data submitted to the platform is owned by a project, and a caller
acts on behalf of one project when writing or deleting. Callers who belong to exactly one
project can omit `project_name` — the platform infers it. Callers who belong to several
must name one, and get a clear error naming the remedy if they do not. Reading is not
narrowed this way: reads span every project the caller may read.

Keep the terminology consistent with the **Project** entry in
[`.ai-context/CONTEXT.md`](../../CONTEXT.md) — avoid "workspace", "tenant",
"organisation", and "group".
